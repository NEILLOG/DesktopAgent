# 工作台 UI 規格

這份文件記錄工作台與設定視窗各個操作元件的**已確認**樣式與行為，實作介面時以這裡為準。
規則性的東西（必須遵守的）同時寫在 `agent.md` 第 12 節；這裡放細節。

**設計原則以 `plan/ui-guide/ui-guide.html`（Lumi Design System）為準**，優先於 `plan/ui-guide/` 裡的圖片設計稿與 `RWD原則.md`；各元件的具體規格（尺寸、狀態、行為）以本文件為準。設計有變更時，兩邊要同步更新。

ui-guide.html 的三項核心原則：一般使用者優先，技術資訊按需要呈現；BYOK 一定要清楚顯示供應商、模型與費用歸屬；溫和但不幼稚，專業但不做成管理控制台。

## 1. 外觀

### 1.1 字型（Windows 與 macOS 統一，全部打包進 app）

不依賴系統字型，避免 Windows 11 的中文退回微軟正黑體或新細明體。

| 用途 | 字型 | 授權 |
|---|---|---|
| 英文介面 | IBM Plex Sans | SIL OFL |
| 中文 | Noto Sans TC（靜態 400／500／700） | SIL OFL |
| 程式碼、路徑、指令 | JetBrains Mono（靜態 400／500／700） | SIL OFL |

- 字型檔放在 `Lumi.App/Assets/Fonts/`，設為 `AvaloniaResource`；授權檔放在 `Assets/Fonts/LICENSES/`。
- 在 `AppBuilder.ConfigureFonts` 註冊 `EmbeddedFontCollection`（key 例如 `fonts:Lumi`）。
- 全域定義兩個資源，元件一律引用，不直接寫字型名稱：
  - `LumiUiFont`：`IBM Plex Sans, Noto Sans TC`（英文先走 Plex，中文字元交給 Noto）
  - `LumiMonoFont`：`JetBrains Mono, Noto Sans TC`（程式碼裡的中文註解也有字）
- 中文與等寬字型各放 400／500／700 三個靜態檔；不做子集化（模型輸出是任意文字）。三套合計約 22 MB，可接受。
- **不使用可變字型**：Avalonia 11.3（Skia）不會套用 `wght` 軸，500／700 會停在 400（2026-10-17 在 macOS 實測）。靜態檔由可變字型用 fonttools 切出，來源與做法見 `Assets/Fonts/LICENSES/README.md`。
- Emoji 仍由 `EmojiText` 依字形叢集指定 emoji 字型，與上面的備援鏈並存。
- 字級（`Themes/Typography.axaml`，依 ui-guide.html 第 2 節）：

  | Token | 大小 | 用途 |
  |---|---|---|
  | `LumiFontSizeDisplay` | 28／700 | 頁面標題（每頁只出現一次） |
  | `LumiFontSizeTitle` | 20／700 | 區段標題、歡迎區標題 |
  | `LumiFontSizeBody` | 14／400 | 內文；項目標題同為 14，字重 700 |
  | `LumiFontSizeCard` | 14 | 工具卡片、氣泡內的文字 |
  | `LumiFontSizeCaption` | 11／400 | 輔助說明、時間、停用原因；只補充資訊，不承載主要操作要求 |

- 驗收：
  - 在未安裝額外字型的乾淨 Windows 11 上，中英文與程式碼區塊都是指定字型，沒有出現細明體或正黑體。
  - 1920×1080 在縮放 100% 與 125% 下各確認一次清晰度（Skia 繪字，不走 ClearType）。
  - Windows 與 macOS 同一畫面的換行位置一致。

### 1.2 主題系統

**五套主題 × 淺／深。** 主題只換顏色，不改版面與元件尺寸（ui-guide.html 明文規定），切換後立即生效、不需重啟。

| 主題 ID | 名稱 | 說明 | Accent | Hover | Soft | Text | Background | Border |
|---|---|---|---|---|---|---|---|---|
| `sage`（預設） | 鼠尾草綠 | 柔和、生活化、低刺激 | `#6D927A` | `#5B8068` | `#EAF2EC` | `#29312D` | `#F6F7F4` | `#E3E8E4` |
| `teal` | 清透藍綠 | 清爽、友善、識別度高 | `#238B8E` | `#19777A` | `#E6F4F3` | `#253033` | `#F5F7F7` | `#E2E8E8` |
| `mist-blue` | 霧藍色 | 穩定、熟悉、生產力工具感 | `#5578C8` | `#4568B7` | `#EAF0FC` | `#252B36` | `#F5F7FA` | `#E2E6ED` |
| `indigo` | 清亮靛藍 | 現代、鮮明、AI 科技感 | `#6269D8` | `#5259C6` | `#EEEDFD` | `#292A35` | `#F6F7FA` | `#E5E5EC` |
| `terracotta` | 陶土色 | 溫暖、人文感 | `#EF8354` | `#DC7045` | `#FFF0E8` | `#27272B` | `#F6F5F2` | `#E8E6E1` |

上表是淺色的原則色碼；深色由同一色相推導。完整色值以 `Themes/Palettes/{id}.axaml` 為準。

- **設定**：只存主題 ID（`AppSettings.ThemeId`，ID 清單與預設在 `ThemePalettes`），不存個別顏色。舊設定檔沒有這個欄位、或 ID 不認得時一律讀成 `sage`，設定檔版本號不變。
- **明暗**是另一個設定（`AppSettings.Theme`：跟隨系統／淺色／深色，預設跟隨系統），由 `RequestedThemeVariant` 控制，系統切換時即時生效。設定 › 外觀與操作 可以選主題色票（五張卡片）與明暗（下拉選單）。
- **檔案位置**：每套主題一份 `Lumi.App/Themes/Palettes/{id}.axaml`，內含 Light／Dark 兩個 `ThemeDictionaries`。語意色與程式碼色在 `Themes/Tokens.axaml`，不隨主題變。`ThemeService.ApplyPalette` 換掉 `App.axaml` 合併資源裡的那一份色票；元件一律用 `DynamicResource`，所以即時生效。Fluent 的強調色（核取方塊、選取、進度條）跟著目前主題的 Accent。
- **色碼只能出現在 `Themes/` 資料夾**（`ThemeTokenRuleTests` 強制）；元件只引用 token。
- 光球（`OrbControl`）維持自己的固定色，不隨主題變。程式碼區塊在兩種明暗下都維持深底。

**主題 token**（每份色票檔都要有；名稱為 `Lumi{名稱}Color`／`Lumi{名稱}Brush`）

| 類別 | Token |
|---|---|
| 底色 | `Background`（視窗底）、`Surface`（卡片、輸入框）、`Chrome`（標題列、工具列、側欄）、`SurfaceAlt`（Hover、停用、chip） |
| 邊框 | `Border`、`BorderStrong`（輸入框、次要按鈕） |
| 文字 | `Text`、`TextMuted`、`TextOnSoft`（Soft 底上的文字：選取項目、徽章） |
| 強調 | `Accent`、`AccentHover`、`AccentSoft`、`AccentBorder`、`AccentText`（Accent 色的文字：頭像「L」、eyebrow）、`OnAccent`（Accent 底上的圖示） |
| 訊息 | `UserBubble`／`UserBubbleText`、`AssistantBubble` |
| 主要按鈕 | `PrimaryButton`／`PrimaryButtonText`、`PrimaryButtonHover`、`PrimaryButtonPressed` |

**語意 token**（`Tokens.axaml`，不隨主題變，淺／深各一組）

| 類別 | Token |
|---|---|
| 狀態文字與圖示 | `Info`（執行中、連結）、`Success`、`Danger`、`WarningIcon`、`WarningText` |
| 淡底與框 | `DangerBackground`／`DangerBorder`、`WarningBackground`／`WarningBorder`（失敗與等待的工具卡片、錯誤列、警告） |
| 狀態點 | `SuccessDot` `#55A981`、`WarningDot` `#D99A3E`、`DangerDot` `#BD5335`（ui-guide.html 的固定語意色，淺深相同，只用在圓點，不當文字用） |
| 程式碼 | `CodeBackground`、`CodeText`、`CodeHeader`（兩種明暗相同） |
| 陰影 | `LumiSpriteShadow`（小精靈氣泡與輸入列）、`LumiCardHoverShadow`（可點擊卡片 Hover）。陰影只用在浮起與 Hover，不拿來分隔內容 |

**文字對比 ≥ 4.5:1**（五套 × 淺／深，所有文字組合，`PaletteContrastTests`、`SettingsContrastTests` 驗證）

- 原則的 Muted 色碼在五套都不到 4.5:1，所以文字用的 `TextMuted`、`AccentText` 在同一色相下調深（深色則調亮），直到對 Background、Surface、Soft 都達標；原則的 Muted 色碼不當文字用。
- `OnAccent`（Accent 底上的送出鈕圖示）取白色或 Text 色中對比較高的一個，屬於圖示／標誌，門檻 3:1（terracotta 的 Accent 疊白字只有 2.61，所以圖示用深色）。
- `TextOnSoft` 用在選取項目與徽章，在 Soft 底上達 4.5:1。
- 語意色：Success、Warning 的原色在白底只有 2.85、2.43，所以文字用較深的 `Success`／`WarningText`，原色（Dot）只用在圓點；狀態一律另外有文字，不只靠顏色。
- **已知例外**：歷史上標題列品牌方塊的「L」（`OnAccent` 在 `Accent` 上）曾是 3.85／4.07／4.28:1，只要求 3:1；標題列的 logo 已於 2026-10-24 移除，此例外不再有對應的元素。淺色的 Success／Warning 狀態點在 Surface 上只有 2.35–2.85:1，測試只守下限 2.3:1，狀態另有文字說明。

### 1.3 間距、圓角與圖示

- **間距只用 4／8／12／16／24／32**（`LumiSpace4`…`LumiSpace32`，`Themes/Metrics.axaml`；0 不算間距）。`SpacingScaleRuleTests` 掃描所有 axaml 的 Margin／Padding／Spacing。例外名單（寫在測試裡，各有原因）：整個 `Sprites/` 目錄（氣泡與輸入列的內距決定尺寸，小精靈版面不改）、對話區 `64,24` 與 Composer `64,8,64,16`、Focus 光暈的 `-3`、ComboBox 下拉覆蓋層的 `0,1,1,1`。
- **圓角**：輸入框與下拉 10（`LumiRadiusInput`）、卡片 14（`LumiRadiusCard`）、頁面區域與 Composer 外框 16（`LumiRadiusPanel`）、浮出層（Flyout、MenuFlyout）12（`LumiRadiusFlyout`）。選取的 Menu 項目 10。
- **控制項高度**：輸入框、下拉選單 40（`LumiControlHeight`）；工具列與輸入區下層的按鈕 32；送出／停止圓鈕 36。
- **頁面 Padding**：設定頁 32；工作台對話區 Wide 64、Compact 24、Narrow 16；訊息間距 24（`short` 起 16）。
- **圖示**：一律用 `Themes/Icons.axaml`（Lucide 0.468.0，授權檔 `Assets/LICENSES/Lucide-LICENSE.txt`）加 `Controls/LumiIcon`（線寬 1.75，顏色與前景色共用繼承，放在按鈕裡會跟著按鈕文字色）。不用 Unicode 符號當圖示或按鈕文字（`NoSymbolIconRuleTests`）；例外只有純裝飾的「·」、省略號「…」與用量說明「↑ 輸入 · ↓ 輸出」的方向箭頭（跟著文字念）。

## 2. 工作台主視窗

由上而下：自訂標題列、工具列、訊息流、輸入區（Composer）。底部沒有狀態列。

### 2.1 頂端區：自訂標題列＋工具列

**標題列**（`CustomTitleBar`，高 40，Chrome 底；`ExtendClientAreaToDecorationsHint=True`）

| 位置 | 內容 |
|---|---|
| 左 | 軟體名稱「Lumi」（2026-10-24 起不放 logo 方塊） |
| 右 | 「小精靈模式」按鈕（Soft 底，圖示加文字；回應中停用），其右「設定」齒輪（32×32 無框圖示按鈕，回應中仍可用；M21） |

- Windows：系統按鈕在最右（由系統繪製，保留寬度 138＋8，Avalonia 沒有取得寬度的 API，用常數），齒輪緊鄰其左（間距 8 加 1px 分隔線），小精靈按鈕在齒輪左邊（間距 8）。
- macOS：紅綠燈在左，品牌往右讓出 80；小精靈按鈕與齒輪放最右（小精靈在左、齒輪在最右），沒有分隔線。排列由 `TitleBarLayout` 純函式決定，有單元測試。
- 整條標題列是拖曳面（`BeginMoveDrag`），按鈕自己處理點擊；雙擊空白處最大化／還原。
- 小精靈按鈕位置固定，只切換文字（Wide「小精靈模式」、Compact「小精靈」、Narrow 只剩圖示，最小點擊範圍 36×32），Tooltip 與可存取名稱不變。
- 設定視窗用同一個標題列，但沒有小精靈按鈕與齒輪（`ShowSpriteButton=False`，兩者共用這個開關）。

**工具列**（`ChatToolbar`，Chrome 底，下緣 1px 邊線）

| 位置 | 內容 |
|---|---|
| 左 | 「新對話」「歷史對話」（secondary，高 32，圖示加文字；Compact 起 32×32 純圖示加 Tooltip） |
| 中 | 模型膠囊：狀態點、「供應商 · model ID」、chevron 圖示 |
| 右 | 用量圖示（見 2.3）、「…」對話選項（tertiary 圖示按鈕，開 MenuFlyout）：重新命名對話、匯出為 Markdown、刪除這則對話（M21） |

- 「設定」改由標題列的齒輪開啟；「管理連線與模型…」在模型選單底部（`ModelSwitcher.ManageCommand`）。
- 「…」的動作針對目前這則對話：空對話（沒有任何訊息）三項全停用；回應中只有「重新命名」可用。重新命名用小對話框（`RenameDialog`），規則與歷史抽屜的內聯重新命名共用；刪除先二次確認，流程與歷史抽屜共用；匯出為 `.md`（`ConversationMarkdownExporter`：使用者／Lumi 分段、工具呼叫一行、思考與供應商專屬區塊略過）。
- **BYOK 顯示規則**（ui-guide.html 核心原則）：
  - 膠囊顯示**確切的 model ID** 與供應商，不顯示使用者自訂的顯示名稱（顯示名稱只在模型選單與設定清單當次要文字，不改寫真實模型名稱）。供應商名稱取連線的名稱，連線沒有名稱時退回供應商格式名稱（「Anthropic 原生」「OpenAI 相容」）。
  - Wide／Compact 顯示「供應商 · model ID」；Narrow 改為狀態點加供應商字首方塊（20，Soft 底，英文大寫、中文取第一字）加 model ID，完整名稱在 Tooltip。文字過長以省略號截斷（`MinWidth 120`、`MaxWidth 360`），不推走其他按鈕。
  - Tooltip 三行：「供應商 · model ID」、「連線狀態：已連線／連線失敗／尚未確認」、費用說明。連線狀態不能只靠圓點。狀態點：已連線＝Success、失敗＝Danger、尚未確認＝Warning（Dot token）。
  - **費用說明**固定一句：「實際費用由供應商依模型與 token 用量計算，費用由你的帳號支付。」出現在膠囊 Tooltip、設定的模型設定頁；用量面板有精簡版（「費用由供應商依 token 用量計算，從你的帳號扣款。」）。
  - 還沒有任何模型時膠囊顯示「未設定模型，點此開啟設定」。
- **模型選單**（`ModelPicker`，Flyout，寬 320，Surface 底、Border 框、圓角 12）：搜尋框、依「連線」分組列出模型設定（目前使用的模型＝Soft 底加打勾圖示加文字）、最下方 tertiary「管理連線與模型…」（開設定視窗）。選了模型就改工作台預設模型並自動收起。
- **歷史對話抽屜**：寬 260、Chrome 底；Wide／Compact 內嵌（把訊息區往右推），Narrow 蓋在訊息區上方（Overlay）。選取＝Soft 底加 `TextOnSoft` 文字；收起時整個隱藏（裡面的項目不會被 Tab 聚焦）。搜尋、依日期分組、改名、刪除、載入更多與無障礙見 2.4。
- 對話可以有多個；工作台與小精靈永遠顯示同一則「目前的對話」。

### 2.2 回應中（從送出到 `Completed`／`Failed`／停止，含等待工具確認）

- 「小精靈模式」按鈕與模型切換膠囊停用。**原因不佔版面，改用停用時的 Tooltip**（`ToolTip.ShowOnDisabled`）：「回應中，暫時無法切換」。
- 輸入區的「加入檔案」「加入資料夾」停用，Tooltip「回應中，暫時無法加入」（收音中同樣停用，Tooltip「語音輸入中，暫時無法加入」）；語音輸入的停用原因見 6.2。
- 輸入框仍可打草稿，送出鈕換成「停止」圓鈕，提示文字區改顯示「回應結束後才能送出，期間不能更改上下文」。
- 歷史對話抽屜仍可瀏覽與改名；刪除在回應中停用（2.4）。切換到其他對話前會先停止目前的回應。

**「切換模式」與「開啟查看」是兩件事。** 回應中不能切換模式，也就是不能把作用中的模式從小精靈換成工作台，反過來也一樣；但小精靈回應中，**可以開啟工作台查看**：

- 工作台以「查看中」狀態開啟，工具列下方顯示橫幅（Soft 底）「小精靈回應中，結束後可在這裡繼續」。工作台的輸入框、模型切換、模式切換都停用。
- 可以捲動、展開工具卡片、複製內容。
- 等待中的權限確認可以在**任一邊**回答。一邊回答後，另一邊同步更新成「已允許」或「你已拒絕」。
- 回應結束後，工作台自動解除「查看中」並切到工作台模式（小精靈在開啟查看時就已隱藏）。此時才能在工作台送出訊息。
- 查看中關閉工作台視窗＝回到小精靈、維持小精靈模式。
- 「新對話」同上：先停止目前的回應。

### 2.3 本對話用量（用量圖示與面板，M21）

底部狀態列已移除；模型選單也不再放用量。用量改成工具列右側的**用量圖示**（`UsageRing` 放在 32×32 的按鈕裡，在模型膠囊與「…」之間），點一下開**用量面板**（Flyout，寬 320，`UsageFlyout`）。細節見 `plan/ui-usage-and-topbar.md`，與它不同的地方以 `plan/21-chat-topbar-and-home.md` 的差異表為準。

- **圓環**：直徑 20、線寬 2.5；進度 = 最近一次請求的上下文用量 ÷ 模型的上下文上限。等級：未滿 60% Normal（主題 Accent）、60%–85% Warning（`LumiWarningIconBrush`）、≥ 85% Danger（`LumiDangerBrush`，按鈕右上角加紅點）；還沒有 usage 或上限未知時是虛線軌道（Empty）。Tooltip「上下文 9% · 點一下看詳情」，可存取名稱「本對話用量：上下文 9%」。

### 2.4 歷史對話抽屜（M9 9A～9B）

- **版面**：由上而下是標題「歷史對話」、搜尋框、清單（填滿）、「載入更多」（只在還有下一頁時出現）。寬 260，收起時整個隱藏。開啟時會重新載入第一頁（啟動後第一次開啟也要有清單）。
- **搜尋框**：`TextBox` 樣式與 Focus 光暈（10.3），左側 Lucide 搜尋圖示，佔位字「搜尋標題與內容」。有輸入時右側出現清除鈕（`tertiary` 純圖示 X，Tooltip「清除搜尋」）。
  - 停止輸入 250 ms 才查詢（節流，數字在 `HistoryOptions`）。新的輸入取消前一次的查詢，舊結果晚到也不會蓋過新的。
  - 比對標題與訊息的文字內容（不含工具結果、檔案快照與 thinking），不分大小寫。
  - 搜尋中**不分組**：標題列顯示「N 筆結果」；達到 100 筆顯示「只顯示前 100 筆，請縮小搜尋條件」。命中的字在標題加粗（只在清單裡），標題下一行是命中片段（前後各約 20 字，一行，省略號截斷）。
  - 沒有結果：「沒有符合『…』的對話」。搜尋模式不分頁，「載入更多」隱藏。
  - Esc（搜尋框內）或清除鈕清除搜尋，回到分組清單。
- **日期分組**（瀏覽模式）：今天、昨天、過去 7 天、過去 30 天、更早。依本地時區判斷（午夜換日即時生效）；沒有項目的群組不顯示。群組標題是不能選取的標題列（Caption、Muted）。列內：標題（超過寬度換行）加右側時間（今天 `HH:mm`，其他 `M/d`）。
- **載入更多**：一次 50 則，游標為 (更新時間, id)。`secondary` 全寬按鈕，不做無限捲動（避免焦點跳動）。
- **列的「…」**：游標停在列上或鍵盤聚焦到列時，右側才出現（平常透明但保留版面，不跳動）。`tertiary` 純圖示按鈕，Tooltip 與 `AutomationProperties.Name` 都是「更多操作：改名、刪除」。
  - 選單：「改名」（鉛筆圖示）、「刪除」（垃圾桶圖示）。右鍵與 Shift+F10（或選單鍵）開同一個選單。
  - 鍵盤：F2 改名、Delete 刪除、Shift+F10 開選單。
- **改名**：行內輸入框取代標題，文字全選。Enter 確認、Esc 取消，失去焦點也視為取消。去頭尾空白；空字串或沒有變動＝取消；上限 60 字（超過截斷）。回應中也可以改名（只動標題）。改名目前開著的對話會同步視窗標題。
- **刪除**：先經過確認對話框（`ConfirmDialog`，確認鍵 `danger`「刪除」，**預設焦點在「取消」**），內文：「要刪除『標題』嗎？這則對話的訊息、加入的檔案清單與圖片附件會一併刪除，無法復原。」
  - 回應中（不論是不是目前的對話）停用，「…」選單的刪除項目 Tooltip 寫出「回應中，暫時無法刪除」。
  - 刪除的是目前開著的對話：導向清單中的下一則，沒有就開新的空白對話；輸入框草稿與上下文列一併清掉。刪除其他對話不影響目前的對話。
- **無障礙**：純圖示按鈕（「…」、清除鈕）都有 `ToolTip.Tip` 與 `AutomationProperties.Name`；群組標題列不能選取；搜尋框有 `AutomationProperties.Name`；改名輸入框有名稱。「…」不在 Tab 順序上（每列一個會讓 Tab 鏈過長），列操作改用 F2、Delete、Shift+F10、選單鍵；Tab 進到清單後用方向鍵移動（移動即選取，與原本一致）。
- **小精靈對話**（M22）：小精靈有一則固定的專屬對話（id 存在 `app_meta` 的 `sprite_conversation_id`，標題「與小精靈的對話」）。它**固定在清單最上方**，不分組、不受分頁影響，帶 sparkle 圖示與「小精靈」標籤；還沒建立時不顯示，搜尋時符合才出現。它的「…」與工作台第二列「…」沒有「刪除」，改成「清除內容」（確認後刪掉全部訊息與整理紀錄，保留對話與標題）。進入小精靈模式時切到這則，回到工作台時開回原本那則；回應中切換會等回應結束。

## 3. 訊息流

- **歡迎區**：對話沒有任何訊息（且不在載入既有對話中）時顯示：Soft 底的圖示方塊（64，圓角 16，sparkle 圖示）、區段標題（20／700）「今天想請 Lumi 幫什麼忙？」、Caption 副標「輸入問題，也可以加入檔案或資料夾。」。Narrow 隱藏副標；高度 < 600 整個隱藏。
- **使用者訊息**靠右：上方是「你」（14／700）與時間（Caption），送出時帶的檔案、資料夾、圖片以小 chip 顯示在氣泡上方（重開程式後仍在，來自訊息裡存的快照），下方是 UserBubble 底色的氣泡（圓角 14，內距 16,12）。
- **助理訊息**靠左：左側 32 的圓形頭像（Soft 底，`AccentText` 色的「L」），右側是名稱「Lumi」與時間、**淡底氣泡**（`AssistantBubble`，圓角 14，內距 16,12）、動作列。氣泡是對話內容，不算卡片；裡面的程式碼區塊、工具卡片算第一層。
- 串流中的 Markdown 邊收邊渲染。**思考過程**（`ThinkingDelta`）在氣泡內，預設收合（進階區段樣式：無框、Muted 標題加 chevron），標題為「思考過程 · N 秒」。
- **程式碼區塊**：深底（兩種明暗相同）、圓角 12。標題列（`CodeHeader` 底）左側是語言標籤、右側是「複製」圖示按鈕，固定在上方，**不隨程式碼水平捲動**；內層水平捲動、不折行，等寬字 13。
- **動作列**（助理訊息下方，全部 tertiary）：複製（圖示加文字，按了變打勾與「已複製」）、重新產生（只有最後一則）、這一輪的 `↑ 輸入 · ↓ 輸出 tokens`（**預設不顯示**；設定 › 外觀與操作 › 進階勾選「在每則回答下方顯示 token 用量」才出現，立即生效）。沒有評價（👍👎）按鈕（M20 移除）。Compact 起文字隱藏，只剩圖示。
- **訊息寬度**（`FractionWidthLimiter`，取對話區內容寬度的比例與像素上限中較小者；不用 Converter）：Wide 助理 ≤ 820 且 ≤ 內容區、使用者 ≤ 72%；Compact／Narrow 助理 92%、使用者 80%。使用者靠右、助理靠左，窄版也不改成滿版。Narrow 隱藏時間與「你」、頭像縮到 24（助理名稱保留）。
- 使用者按停止後，在訊息尾端顯示「你已停止這次回應」。
- **選取文字**（M22）：使用者訊息、思考過程、Markdown 回答的每個段落（含程式碼、表格）都可以拖曳選取（`EmojiTextBlock` 繼承 `SelectableTextBlock`），`Ctrl/Cmd+C` 複製；右鍵選單「複製」（沒有選取時複製整段）。同一則 Markdown 回答裡可以跨段落、清單、表格、程式碼拖曳選取（`MarkdownView` 接手按下與拖曳，複製時各區塊用換行接起來；清單符號不在選取範圍內）；雙擊選字、三擊選整段；不能跨訊息選取。連結照樣可點，從連結上拖曳是選取。小精靈氣泡與按鈕裡的文字不開放選取。
- **上下文整理**（M22）：用量超過模型上限 80% 時，送出前先把較早的工具結果換成一行省略說明；仍超過 70% 時請同一個模型把較早的對話摘要（最近兩輪原樣保留）。整理只影響送給模型的內容，原始訊息、歷史、匯出都不變。摘要整理中，訊息區底部顯示「正在整理對話…」（小精靈氣泡同一句）；整理的位置有一條分隔線「以上內容已整理成摘要」，「查看摘要」展開全文（可選取），只顯示最新一次。整理失敗時在訊息區底部顯示 Warning 提示（「知道了」關閉），不擋送出。供應商回「超過上限」時自動整理並重送一次。
- API 失敗：在最後一則訊息下顯示錯誤列（Warning 淡底：原因加「對話內容已保留。」），按鈕「重試」（primary，該區唯一）與「換模型重試」（secondary，開模型選單）。一次性提示（例如設定檔損毀已改用預設）同樣用 Warning 淡底，只有一顆 tertiary「知道了」。
- 錯誤文字的補充（M9 9C）：連線失敗且系統沒有任何可用網路介面、連線目標不是本機或內網時，句尾補「看起來沒有網路連線。」；目標是 localhost 或內網主機時改說「確認服務是否已啟動」，不補離線的句子。429／529 帶 `Retry-After` 時，「請稍後再試」換成「約 N 秒後再試」（超過 60 秒為「約 N 分鐘」）。錯誤列與小精靈氣泡用同一段文字。

## 4. 工具呼叫卡片

- 卡片＝`card` 樣式（Surface 底、Border 框、圓角 14）；**預設收合**，但標題必須明確，不展開也看得懂做了什麼。標題整列是一顆按鈕（Hover／Pressed 不換底），格式固定為：

  `狀態圖示  動作 · 對象 · 結果摘要  …  耗時  chevron`

  例：「讀取檔案 `plan/00-overview.md` · 182 行」、「執行 `dotnet build` · 失敗（exit 1）· 3 個編譯錯誤」。

  執行中（M19）：工具可以回報進度（`ToolContext.Progress` → `ToolCallProgress` 事件），標題最後一段從「執行中…」換成最新的進度文字，例如「爬取網站 · intranet.example.com · 第 3／10 頁」；等待確認時不顯示進度，完成後換成結果摘要。進度只給畫面看，不存檔、不送給模型。
  動作名稱由工具的 `Descriptor` 提供顯示名稱（繁中）；結果摘要由工具回傳，不由 UI 猜。
- **狀態圖示**（Lucide，形狀各不相同，不只靠顏色；顏色用文字等級的 token，不用 Dot）：

  | 狀態 | 圖示 | 顏色 | 卡片 |
  |---|---|---|---|
  | 執行中 | loader，持續轉圈（只有執行中才有動畫） | `Info` | 一般 |
  | 成功 | check | `Success` | 一般 |
  | 失敗 | x | `Danger` | `DangerBackground` 底與框 |
  | 等待允許 | alert-triangle | `WarningIcon` | `WarningBackground` 底與框 |
  | 已拒絕 | ban | `TextMuted` | 透明度 0.75 |

  chevron：收合 chevron-right、展開 chevron-down。
- 執行中與等待允許的卡片**強制展開、不能收合**。
- 展開後顯示參數與結果（小標籤用 Caption／600／Muted，內容用等寬字）；結果超過 6 行只顯示前段，提供「顯示完整輸出」與「複製」（tertiary small）。
- 同一輪連續 3 個以上的工具呼叫合併成一張群組卡，標題例：「3 個工具呼叫 · 讀取 2 個檔案、搜尋 1 次，全部成功」。任一失敗時群組標題改為失敗色並寫出失敗項目。群組卡裡的工具卡片是第二層（卡片巢狀最多一層）。

- **圖片結果**（M22，`generate_image`／`edit_image`）：結果區顯示縮圖（最寬 320、等比）；點縮圖或「開啟圖片」用系統看圖程式開啟，「開啟資料夾」開圖片所在的資料夾（「圖片／Lumi」）。檔案被移走時顯示檔名與「檔案已移動或刪除」。圖片只顯示，不送回模型。

## 5. 工具權限確認

確認區**嵌在工具卡片內**，不跳 modal；對話迴圈暫停直到使用者選擇。按鈕依工具的權限等級（`agent.md` 第 8 節）決定，並遵守按鈕層級（10.1）：**每個確認區最多一個 primary（或 danger）**。

| 權限等級 | 是否詢問 | 按鈕（層級） |
|---|---|---|
| `ReadOnly` | 不詢問 | — |
| `Write` | 詢問 | 允許一次（primary）／本次對話都允許（secondary，此等級）／拒絕（tertiary） |
| `Network` | 詢問 | 允許一次（primary）／本次對話都允許（secondary，此等級）／拒絕（tertiary） |
| `Destructive` | 每次詢問，不提供記住選項 | 允許執行（danger，紅框紅字）／拒絕（secondary）；沒有 primary |

- 「本次對話都允許」只存在記憶體，不寫入設定檔；重開程式或開新對話後失效。內建工具依權限等級記住；**MCP 工具依工具名稱記住**（允許一個外部工具不會連帶允許其他外部工具，M16 D13）。
- 「永遠允許」（M15）：在設定 › 工具為 `Write`／`Network` 工具設定後，不再出現確認區，卡片顯示「已允許（永遠允許）」。`Destructive` 與 `memory_save` 不提供這個選項。
- 瀏覽器工具（M18）的確認卡片：對象是元素描述加主機，例如 `button "送出" · example.com`（取自最近一次快照）；輸入文字類的工具**不在卡片上顯示輸入的內容**（只寫字數）；「本次對話都允許」只對瀏覽器工具生效，不連帶其他寫入工具。
- 網址警告（M17）：工具會連到對話中沒出現過的網站、或搜尋引擎網址時，確認區在權限說明下方多一到數列警告（Warning 淡底、三角圖示、Warning 文字）；搜尋引擎網址不提供「本次對話都允許」。這兩種情況即使設了「永遠允許」也一定出現確認區。
- 確認區顯示這次會做什麼：寫入檔案顯示路徑與增減行數，`Destructive` 顯示完整內容與工作目錄，並標上「無法復原」（Danger 色）。
- 拒絕：回傳 `ToolResult.Error("使用者拒絕執行")` 給模型，由模型決定改做法或說明。
- 按停止：取消等待中的確認，結束這一輪回應。
- 每次的選擇都記錄在對話裡，卡片顯示「已允許」或「你已拒絕」。
- 小精靈模式下的確認方式：見第 8.3 節（在氣泡內完成，兩邊的回答會同步）。
- 刪除連線／模型、清除金鑰、放棄變更等確認對話框（`ConfirmDialog`，寬 420）：取消是 secondary；一般確認是 primary，**破壞性確認是 danger**（紅框紅字），Esc 取消。**破壞性確認的預設焦點在「取消」**（M9 9B）；確認鍵仍是 `IsDefault`，回車時實際會觸發哪個按鈕，需在實機確認（見 plan/09 待人工確認）。

## 6. 輸入區

輸入區（`ChatComposer`，`InputArea`）是**一個圓角 16 的外框**（Surface 底、1px Border；輸入框取得焦點時外框變 Accent 邊框，拖放檔案進來時 2px Accent 邊框），外框左右 Margin Wide 64／Compact 24／Narrow 16，與對話區的左右 Padding 對齊。輸入框自己沒有外框。版面分**兩層**：

- **上層**：上下文列（有項目才出現，見 6.1）與輸入框（`MinHeight` 64，`short` 起 48 即兩行高；`MaxHeight` 160，超過改捲動）。
- **下層**：左側「加入檔案」「加入資料夾」「語音輸入」（tertiary，高 32，圖示加文字；Compact 起純圖示加 Tooltip）；右側是提示文字區與送出／停止圓鈕。輸入區永遠完整可見，附件 chip 換行也不會推走送出鈕。

### 6.1 上下文列（輸入框上方）

- 標題「此對話的上下文」，加入的檔案與資料夾以 chip 常駐顯示，每個都可移除（chip 右側 20×20 的 tertiary X 圖示按鈕）；右側顯示預估 token（`≈ 18.2K tokens`）。
  - 上下文列只在有項目時出現；預估 = 對話歷史＋待送出的項目＋輸入框的草稿，超過模型的上下文上限時顯示警告圖示（Tooltip 說明這是估算，實際用量看模型選單的「本對話」）。
  - chip：名稱＋一小段說明（資料夾的項目數、檔案大小，或問題：找不到、不是文字檔、太大由模型按需讀取、不支援的圖片格式、圖片太大）；已經帶進過訊息的標「已帶入」；有問題的 chip 用 Warning 淡底。圖片 chip 顯示縮圖。
  - 移除已帶入的項目時顯示一次性的說明：模型之前看過的內容仍在這則對話裡（範圍縮小了，但已送出的內容收不回來）。
  - **回應中不能加入或移除**（範圍不能在工具執行到一半時改變），按鈕停用並以 Tooltip 說明原因。
- 上下文屬於整則對話，不會因為送出訊息而消失（M4）。
- 檔案：文字直接放入；圖片用圖片格式送出。資料夾 chip 顯示檔案數，用 Soft 底加 Accent 邊框與檔案區分；只送檔案樹，內容由範圍限定的工具讀取。
- 加入方式：輸入區的「加入檔案」「加入資料夾」按鈕、拖放（整個輸入區，拖進來時外框變 Accent）、貼上截圖（Ctrl／Cmd+V，剪貼簿有圖片時加成圖片項目，否則照一般貼上文字）。種類由內容判斷：資料夾、圖片（檔案開頭的位元組）、其他檔案。

### 6.2 輸入框與按鈕

- Enter 送出、Shift+Enter 換行；高度隨內容增加，最高 160 後改捲動。
- **語音輸入**：麥克風按鈕可用（M6）。停用時 Tooltip 寫出原因（`ShowOnDisabled`，不另外佔版面）：尚未設定服務端點→「尚未設定語音服務，請到設定裡的語音頁」；端點有誤→「語音服務端點有誤，請到設定裡的語音頁修正」；沒有 Token 或端點主機與 Token 綁定的主機不同→「語音服務尚未設定 Token」；回應中（含小精靈回應時的查看中）→「回應中，暫時無法語音輸入」；已在錄音、轉寫中→「已在錄音或轉寫中」；上一段錄音還沒處理→「上一段錄音還沒處理，請先重試或放棄」。可用判斷只看設定（端點、Token 的 hint 與綁定主機），不讀 `ISecretStore`，所以開啟麥克風不會跳出鑰匙圈授權視窗。
- **送出**：36×36 圓鈕，Accent 底、arrow-up 圖示（`OnAccent`）；Hover／Pressed 換 `AccentHover`；輸入為空時停用（Soft 底加 Muted 圖示）。它是圖示按鈕，不算 primary 文字按鈕。**停止**：同尺寸，Primary 底、square 圖示；回應中取代送出鈕，兩者位置相同、不跳動。收音中送出鈕與提示文字隱藏（收音面板有自己的「停止並送出」）。
- **提示文字區**（下層中間偏右，同一位置互斥顯示）：平時是操作提示「Enter 傳送 · Shift + Enter 換行」（Compact 起隱藏）；回應中改顯示「回應結束後才能送出，期間不能更改上下文」（過長以省略號截斷）。

### 6.3 語音輸入（M6）

收音面板（`VoicePanel`）**取代**輸入框（輸入框隱藏），高度與輸入框相同（Normal 64、short 起 48），切換狀態時版面不跳動。下層工具列的「加入檔案」「加入資料夾」停用並寫出原因（Tooltip），送出鈕與提示文字隱藏。焦點跟著狀態走：開始收音時停在「停止並編輯」（不會直接送出）；轉寫時停在「取消」；失敗時停在「重試轉寫」；回到閒置時回到輸入框。

- **收音中**：Danger 圓點（`LumiDangerDotBrush`）、`mm:ss / 01:30`、波形（`LevelWaveform`，32 根長條，Accent，新的音量往左推）；三個按鈕：取消（tertiary，X 圖示）、停止並編輯（secondary，方形圖示）、停止並送出（primary，箭頭圖示）。每個按鈕都有 Tooltip 與無障礙名稱；Compact 起只剩圖示（沿用 `collapsible`，Tooltip 仍在）。**Esc 取消錄音**（焦點在輸入區內時）。達 90 秒自動結束，照「停止並編輯」處理。
- **轉寫中**：轉圈圖示（和工具卡片執行中相同的動畫）＋「正在辨識語音…（錄音長度 00:12）」＋取消（tertiary）。取消會取消請求並丟掉錄音。兩種停止都先經過這一步。
- **失敗**：Danger 淡底（同設定頁連線失敗的樣式）＋三角圖示＋「語音轉寫失敗」與服務給的一句說明（繁中，不含伺服器內文或 Token），按鈕「重試轉寫」（primary，用保留的錄音再轉一次）與「放棄」（tertiary，丟掉錄音回到閒置）。錄音會保留到重試成功、放棄，或切換對話（切換對話時失敗的錄音一併丟掉）。
- **提示（Notice）**：錄音太短（少於 0.5 秒）「錄音時間太短，已忽略」、沒有聲音（麥克風權限）「沒有收到聲音，請確認麥克風權限」、轉寫結果空白「沒有聽到內容」，顯示在輸入區上方的 Caption；下一次輸入或開始錄音時消失（不另外計時）。
- **停止並編輯**：轉寫文字放進輸入框（輸入框已有草稿時以換行接在後面），上方出現「語音轉寫」標籤（Chip）；使用者改動或清空文字後標籤拿掉。**不送出**，焦點移到輸入框。
- **停止並送出**：同一則對話、沒有在回應、輸入框是空的，轉寫完成後走現有的送出路徑。其他情況（對話已改變、回應中、輸入框已有草稿）改成放進輸入框並提示（「回應中或對話已改變，語音結果已放進輸入框，請確認後再送出」／「輸入框已有文字，語音結果已附加在後面，請確認後再送出」），不自動送出。
- **切換對話**：收音或轉寫中切換對話（或小精靈開始新對話）會**取消**收音與轉寫，不詢問；回應開始時若正在收音也取消（轉寫中的結果仍照上一條規則處理）。
- 無障礙：狀態用文字呈現（「收音中 00:12」、「正在辨識語音…」、「語音轉寫失敗」），不只靠顏色；面板的無障礙名稱跟著狀態文字。Avalonia 11.3 沒有可用的 live region 屬性，所以靠焦點搬到面板的預設按鈕讓讀屏軟體讀出狀態。

  - 兩行 Caption：「啟用與關閉從下一則新對話開始生效；進行中的對話維持原本的工具。」「確認方式改了立即生效。」；目前預設模型關閉「啟用工具」時，另有 Warning 淡底的整行說明。
  - 依群組列出（內建：一般、讀取檔案、寫入檔案、筆記與對話、提醒與計時、長期記憶、小精靈；MCP：每個已啟用的伺服器一組，排在內建之後），群組之間用分隔線。群組列是三態勾選框（全開／全關／部分）加群組名稱加「已啟用 n／m」。
  - 工具列：勾選框、顯示名稱（14／600）、權限徽章（唯讀／寫入／網路／破壞性，破壞性用 Danger 淡底）、模式（只限工作台／只限小精靈）、說明（Muted）、工具名稱（等寬 Caption）。右欄是確認方式：唯讀「不需確認」；不能永遠允許的「每次都會詢問」（附 Tooltip 說明原因）；其他是「每次詢問／永遠允許」下拉（改成「永遠允許」前先確認）。
  - 不能關閉的工具（`show_details`）勾選框停用並寫出原因；記憶關閉時記憶群組寫說明。
  - MCP 工具另有「權限等級」下拉（唯讀／寫入／網路／破壞性）與伺服器的建議（「伺服器標示：唯讀」等，只是提示）；改成「唯讀」前先確認；伺服器未連線時顯示上次取得的工具與說明。
  - 底部「全部恢復預設」（secondary，先確認；已是預設時停用，旁邊寫原因）。
- **MCP 伺服器**：沿用「AI 連線」的清單（260）＋詳細版面，< 900 時上下排。
  - 清單卡片：字首方塊、名稱、副標（本機指令 · 指令檔名／遠端 · 主機）、狀態文字加圓點（已連線 · n 個工具／連線中…／連線失敗／已停用）；最後一列虛線「新增伺服器」；清單下方「從 JSON 匯入」（secondary）。
  - 詳細：名稱、連線方式（分段：本機指令／遠端 HTTP）、指令與參數（一行一個）或 URL、環境變數／標頭（名稱＋遮罩的值；已儲存的值只顯示「已設定」與更換、移除）、「啟用」「也在小精靈使用」、進階（代號、工作目錄、逾時秒數，有錯誤時自動展開）。Caption 說明風險與祕密的存放（值只存在這台裝置、結果會送到模型供應商）。連線失敗用 Danger 淡底加三角圖示加原因文字。底部：刪除（danger，靠左，先確認）、測試連線（secondary）、儲存（primary）。
  - JSON 匯入取代詳細區：貼上 → 解析 → 預覽（會改名的、有錯誤的逐筆標示）→ 匯入 n 筆。

**外觀與操作**

- 「主題色票」區段：**五張可選取的色票卡片**（`ListBox.cards`，每張寬 200），每張顯示名稱、說明、四個色塊（該色票自己的 Accent／Hover／Soft／Text 的淺色變體，不是目前主題的 token）；選取的卡片＝Soft 底加 Accent 邊框加「使用中」文字徽章。點選立即套用，只改顏色不改版面；可用 Tab、方向鍵、空白鍵或 Enter 操作。
- 分隔線，然後「明暗」區段：「顯示模式」下拉選單（跟隨系統／淺色／深色）。
- 分隔線，然後「筆記資料夾」區段（M10 10B）：路徑文字欄位（空白＝預設的 `文件/Lumi/notes`）、「選擇資料夾」（secondary）、「恢復預設」（tertiary，使用預設位置時停用）。沒有儲存鈕：Enter 或離開欄位時套用，選擇資料夾立即套用；不合法的路徑顯示原因並保留輸入的文字。路徑可含環境變數（`%VAR%`、`$VAR`），所以選到含 `$` 或 `%` 的資料夾會被當成變數而顯示錯誤。資料夾可以是 Obsidian vault，Lumi 只處理檔名符合 `yyyy-MM-dd.md` 的檔案。

**小精靈**（選了立即生效，沒有「儲存」鈕，所以沒有 primary）
- 左邊是預覽卡（240×240），用同一個角色即時播放右邊所選的狀態；寬 < 900 時移到上方。
- 角色清單（可選取卡片）：縮圖（素材型角色的 `preview.png`）、名稱、作者與版本、「程式型／素材型」標籤、「使用中」徽章；換角色立即生效，小精靈視窗的位置不動。
- 清單下面：「重新載入」（載入中顯示「載入中…」並停用）、「開啟角色資料夾」（兩者都是 secondary）、角色資料夾的路徑（Windows `%APPDATA%\Lumi\sprites`、macOS `~/Library/Application Support/Lumi/sprites`）。
- 「載入失敗與警告」：目錄掃描的結果加上素材型角色解碼時才發現的問題，每項一行（失敗用 Danger 淡底、警告用 Warning 淡底，各有三角圖示與「載入失敗」「警告」文字），寫出資料夾、欄位與原因。失敗的角色不在清單裡；有警告的照常可用。選用的角色被移走時，清單顯示第一個，設定裡的選擇不變，角色回來、重新載入就自動換回去。
- 尺寸：小 64／中 80（預設）／大 104，切換時角色中心不跳動。
- 角色語氣開關（光球沒有語氣，說明文字會告訴使用者）；語氣只影響說話風格，和人設衝突時以人設為準。
- 狀態預覽：十個狀態各一列；角色沒有專屬表現的狀態標示「沒有專屬表現，改用「待機」」這類退化說明（規則和小精靈視窗用的 `SpriteStateResolver` 相同）。

**語音**（M6；分類排在最後，索引 5）

- 頁首：eyebrow「語音」、標題「Whisper 語音辨識」、說明；沒有頁首動作（對齊人格頁，底部動作列放「測試連線」「還原」「儲存」）。
- 區段「服務」（`FormField`，不包卡片）：
  - **服務端點**（必填）：完整網址，必須是 https（只有 localhost、127.0.0.1、::1 可用 http）；輸入時即時顯示端點規則的原因（`SpeechEndpointRules`，例如「端點不可包含查詢字串」）。預設留空；留空時儲存與測試停用，原因寫「請先輸入服務端點」。
  - **語言**（選填）：文字欄位加四個 tertiary 快選「留空（服務判斷）」「中文 zh」「英文 en」「日文 ja」。留空＝不送 `language`，由服務端判斷。
  - **逾時秒數**（必填）：整數 5 到 600，超出範圍或不是整數時錯誤文字寫在欄位下方，儲存與測試停用。
  - Caption：「語音會連同錄音與對話 ID（session_id）送到你設定的服務。」「憑證不受信任時，請把公司的內部 CA 安裝到系統。」
- 區段「Token」：
  - 已設定：一行「已設定 · 結尾 xxxx」，右側「更換」（secondary）、「清除」（tertiary；先確認）。按「更換」後出現遮罩輸入框，右側「取消更換」。
  - 未設定：遮罩輸入框（可切換顯示）。
  - **Token 綁定端點主機**：Token 記錄的是寫入時端點的主機（`SpeechSettings.TokenHost`）。草稿端點的主機與綁定的主機不同（或端點被清空）時，狀態行換成 Warning 文字「端點主機已變更，請重新輸入 Token」，輸入框直接顯示；測試連線不會把舊 Token 送到新主機。儲存時若沒有輸入新 Token，舊的會被刪除。
  - Caption：「Token 需具備 WHISPER_API 權限；只存在這台裝置。」
- 動作列：左邊是訊息（「已儲存。」或錯誤）與停用原因（Caption）；右邊「測試連線」（secondary）、「還原」（secondary，丟掉未儲存的草稿與輸入中的 Token）、「儲存」（primary，這一區唯一的 Primary）。
  - 測試連線用**編輯中、尚未儲存**的端點、語言、逾時，Token 用輸入的；沒有輸入時用已儲存的（主機要相同）。測試中顯示「測試中…」並停用按鈕。成功＝Success 淡底加打勾加「連線成功，服務接受了這組端點與 Token。」；失敗＝Danger 淡底加三角圖示加「連線失敗」與原因（不含伺服器回應內文，也不含 Token）。
  - 任何欄位改動就清掉舊的測試結果。

**網路**（M17；分類排在最後，索引 7）

- 頁首：eyebrow「網路」、標題「網路與 Proxy」、說明（設定會套用到 AI 模型、語音、遠端 MCP 與網路工具）；沒有頁首動作。版面同語音頁：單欄、最大寬 560、`section-title` 分區、底部動作列。
- 區段「Proxy」：
  - **連線方式**（必填，直排 RadioButton，綁整數索引）：跟隨系統設定（預設）／使用 PAC 網址／手動指定 Proxy／不使用 Proxy；說明「公司網路通常選「跟隨系統設定」就可以。」
  - **PAC 網址**（只有 PAC 模式）、**Proxy 位址**與**不經過 Proxy 的位址**（多行，一行一個；只有手動模式）。
  - **Proxy 驗證**（不使用 Proxy 時隱藏）：不需要／使用目前登入的帳號（Windows 網域，預設）／帳號與密碼。選帳號與密碼時才顯示**帳號**（可寫「網域\帳號」）與**密碼**（已設定時「已設定」加「更換」；未設定時遮罩輸入框加「顯示」）。密碼只存在這台裝置。
- 區段「網站與網路工具」：**自動使用 Windows 登入的網站**（多行，萬用字元如 `*.corp.example.com`；只套用在網路工具）、**逾時秒數**（5～120）、一段 muted 說明「Lumi 不提供網路搜尋…」。
- 區段「測試連線」：**測試網址**（預設 `https://example.com/`，不存進設定）；結果樣式同語音頁（成功＝Success 淡底加打勾；失敗＝Danger 淡底加三角圖示加原因）。測試用**編輯中、尚未儲存**的設定，密碼用輸入的、沒輸入就用已儲存的；任何欄位改動就清掉結果。
- 動作列：訊息與停用原因（Caption）；「測試連線」（secondary）、「還原」（secondary）、「儲存」（primary，唯一）。只檢查目前顯示中的欄位。

**網路頁的「瀏覽器」區段**（M18；在「測試連線」之後，用分隔線隔開，三項都**立即生效**，不算未儲存的變更）

- **使用的瀏覽器**：三個 RadioButton（綁整數索引）「自動（Edge 優先，其次 Chrome）」「Microsoft Edge」「Google Chrome」，下方一行偵測結果（`找到：Microsoft Edge 138.…、Google Chrome 155.…`；找不到時 Warning 文字，有裝但選的沒裝時顯示原因）與「重新偵測」（tertiary）。下次開啟瀏覽器時生效。
- **顯示瀏覽器視窗**：CheckBox，說明「開啟後可以看到 Lumi 的每一步操作，偵錯時很有用。」預設關閉（背景執行）。
- **登入狀態**：「清除瀏覽器的登入狀態」（secondary；先確認），Caption 說明 Lumi 使用自己專屬的設定檔、不讀平常瀏覽器的 Cookie 與密碼。
- 最後一行 muted：「頁面內容與截圖會送到你選擇的模型供應商。」

## 8. 小精靈模式的對話

角色本身的狀態與動畫見 `docs/sprite-dev-guide.md`；這一節只管殼的對話介面：氣泡、輸入列、權限確認、語音。

**輸入列因麥克風鈕重排**（M6 6E）：輸入列的外框仍是 300×48，氣泡與角色的版面沒有改。輸入列裡由左到右是麥克風圓鈕 36×36（座標 (7,6)）、輸入框（x=51 起，寬 198，高 12，位置 (51,18)）、送出鈕 36×36（座標 (257,6)）。加了麥克風後輸入框從 240 縮成 198，以容納麥克風。收音時整列換成收音列（8.4），仍在同一個框內。輸入列的尺寸由 `SpriteInputBarLayoutTests` 鎖定（數值見該測試）。`Sprites/` 目錄是間距規則的例外（1.3）；換成 M12 的 token 與按鈕層級的做法不變。

### 8.1 氣泡

- **高度上限**（M22）：氣泡（含提醒卡片）最高到預留區頂端往下 16（陰影向上超出的距離），不再頂到視窗頂端；超過時在氣泡內捲動，內容變動時停在最下面（最新的回答與按鈕）。

- 寬度上限 280；回答最多兩句、約 60 字、不用 Markdown（`agent.md` 第 9 節）。
- 同一時間只顯示**最新一則**，不顯示上一輪，也不重複顯示使用者的問題（語音送出例外，見 8.4）。
- 思考或呼叫工具時，只顯示一行狀態，文字沿用工具卡片標題，例如「讀取檔案 · plan/00-master-plan.md」。
- 回覆以串流方式寫進氣泡。
- 完成後停留 8 秒淡出；滑鼠停在氣泡上時暫停計時。
- 等待確認、錯誤這兩種氣泡不會自動淡出。
- 有完整內容時（呼叫了 `show_details`，或回答被截斷），氣泡底下顯示「在工作台開啟完整內容」連結，由使用者自己點，不自動打開。
- 錯誤：一句說明，加上「重試」（primary）「在工作台查看」（連結）；金鑰問題帶「開啟設定」（secondary）。
- 顏色與工作台共用 token（含主題色票，跟隨明暗）。另外加細框線和陰影（`LumiSpriteShadow`），確保在任何桌面背景上都看得清楚。

### 8.2 輸入列

- 滑鼠靠近才浮現：麥克風（語音輸入，tertiary 圓鈕）、「問小精靈…」輸入框、送出。
- 麥克風停用時 Tooltip 寫出原因（`ShowOnDisabled`）：沒有設定語音、回應中、另一個視窗正在語音輸入、小精靈暫時隱藏中。
- 送出鈕與工作台相同（Accent 底圓鈕）；回應中可以打草稿，送出鈕換成停止（Primary 底）。
- 語音草稿（停止並編輯，或送出被規則擋下來）：輸入框前面有小標籤「語音」，使用者改動文字後拿掉；標籤佔用的寬度從輸入框扣掉。

### 8.3 工具權限確認

- **在氣泡內就能完成**，不需要切回工作台。光球進入 `Attention` 狀態，氣泡加上警示色外框。
- 預設精簡版：一句說明、對象（路徑或網址，等寬字）、「允許」（primary）「拒絕」（tertiary），再加一個「更多選項」連結。
  - 精簡版的「允許」等於「允許一次」。
- 網址警告（M17）以 Caption 大小的 Warning 文字顯示在對象下方；搜尋引擎網址的「更多選項」不顯示「這則對話都允許」。
- 「更多選項」在氣泡內展開，提供：允許一次（primary）／這則對話都允許（secondary）／拒絕（tertiary）／在工作台檢視（連結）。
- 「在工作台檢視」會以查看中狀態開啟工作台（見 2.2），並捲到那張工具卡片；在哪一邊回答確認都可以。
- `Destructive`：標上「無法復原」，完整列出所有對象，只有「允許刪除」（danger）「拒絕」（secondary），沒有更多選項。
- 允許後：氣泡回到工具執行狀態（「已允許 · 寫入檔案中…」）。
- 拒絕後：模型接著回答，一樣限制在兩句內。

### 8.4 語音

- 點輸入列的**麥克風**開始錄音（麥克風停用時 Tooltip 寫出原因）。點光球保留給戳、拖曳等互動。
- **收音列**取代輸入列（同一個框內，尺寸不變）：
  - 收音中：Danger 紅點、計時 `mm:ss`、波形（`LevelWaveform`），三個圓形圖示鈕：取消（tertiary，X）、停止並編輯（secondary，方形）、停止並送出（primary，箭頭）。每個都是純圖示，有 Tooltip 與無障礙名稱。
  - 轉寫中：轉圈圖示＋「正在辨識語音…」＋取消（tertiary）。
  - 失敗：警示圖示＋一句錯誤（完整文字在 Tooltip），「重試轉寫」（primary）與「放棄這段錄音」（tertiary，純圖示加 Tooltip）。氣泡同時顯示同一句錯誤與文字按鈕「重試轉寫」「放棄這段錄音」，不自動淡出（比照錯誤氣泡）。
- **Esc 取消錄音**（收音中）。小精靈暫時隱藏或切換到工作台模式時，小精靈開始的錄音會取消，不在背景錄音。
- 光球狀態：收音中為 `Listening`，轉寫中為 `Transcribing`，失敗為 `Error`（直到錯誤氣泡被處理或重試開始）。回應進行中以對話狀態為準；退化由 `SpriteStateResolver` 負責。
- **停止並送出**：同一則對話、沒有在回應、小精靈顯示中、輸入框是空的，轉寫完成後先以小字引用轉寫結果（過長截斷），再進入思考。其他情況（對話已改變、回應中、小精靈隱藏、輸入框已有草稿）改成放進輸入框，並以提示氣泡說明：「回應中或對話已改變，語音結果已放進輸入框，請確認後再送出」「輸入框已有文字，語音結果已附加在後面，請確認後再送出」。
- **停止並編輯**：文字放進輸入框（已有草稿時以空白接在後面），前面標「語音」，不送出。
- **語音提示**（太短、沒有聲音、沒聽到內容）：短暫的提示氣泡，約 4 秒淡出，游標停在上面時暫停計時。提示不會蓋過權限確認與錯誤氣泡。
- 工作台與小精靈共用同一個收音狀態：另一邊在錄音或轉寫時，麥克風停用並寫出「另一個視窗正在語音輸入」。轉寫結果只交給開始錄音的那一邊。
- 權限確認與收音：回應開始時收音會取消（計畫 6D 的規則），所以權限確認不會出現在收音中；確認氣泡出現時照常可以在氣泡內完成。

### 8.5 右鍵選單

開啟工作台、新對話、切換角色…、設定…、暫時隱藏 30 分鐘、結束 Lumi。（「切換角色…」在設定頁有角色清單之後加入。）

- 回應中：「開啟工作台」可以用（以查看中狀態開啟，見 2.2）；「新對話」停用。

### 8.6 模式與視窗

- 兩種模式**互斥**：工作台模式時小精靈隱藏；按工作台的「小精靈模式」＝隱藏工作台、顯示小精靈。上次結束時的模式會記住，啟動時回到它（第一次是工作台模式）。
- 小精靈與工作台**不同時存在**。小精靈模式下從右鍵選單、氣泡連結或托盤「開啟工作台」＝隱藏小精靈並切到工作台模式；小精靈回應中則先以唯讀的「查看中」（2.2）開啟，回應結束才切換成工作台模式。
- 工作台模式下關閉工作台視窗＝結束程式；小精靈模式下（只會在查看中出現）關閉工作台＝回到小精靈。
- 托盤圖示（Windows 通知區域、macOS 選單列）：顯示小精靈、開啟工作台、結束 Lumi。「暫時隱藏」期間可以從這裡提前顯示；暫時隱藏時如果需要權限確認，小精靈會自動顯示。

## 9. RWD（響應式）

依據 `plan/ui-guide/RWD原則.md`（和 ui-guide.html 衝突時以 ui-guide.html 為準）。原則：重新排列而不是整頁縮放；輸入框與送出鈕永遠完整可見（工作台主版面固定 `Auto／Auto／*` 三列，只有訊息區伸縮與捲動）；模型資訊不消失；小精靈入口位置固定；漸進式精簡（先隱藏次要文字，再縮短標籤，最後才改純圖示）；程式碼不強制折行。小精靈視窗不在範圍內。

### 9.1 斷點

| 類別 | 分段 | 條件（進入／離開各有 ±8 緩衝） |
|---|---|---|
| 寬度 | Wide | ≥ 1000（離開要 < 992） |
| | Compact | 620–999（從 Narrow 升上來要 ≥ 628；降到 Narrow 要 < 612） |
| | Narrow | < 620 |
| 高度 | Short | < 700（回復要 ≥ 708） |
| | VeryShort | < 600（回復要 ≥ 608） |
| 設定視窗 | `stacked`（清單＋詳細改上下排） | < 900（回復要 ≥ 908） |

緩衝是為了視窗停在 619/620、999/1000、899/900 附近時不反覆切換。

### 9.2 機制

- 分段判定是純函式 `ResponsiveRules`（`ClassifyWidth`、`ClassifyHeight`、`ClassifyStacked`，吃目前值與上一個分段），邊界由 `ResponsiveRulesTests` 驗證。
- `ResponsiveClasses.Track(window, trackStacked)` 掛在 Window 根節點，監聽 `Bounds`，**只在跨越斷點時**更新根節點的 Classes：`wide`／`compact`／`narrow`，加上 `short`／`veryshort`；設定視窗另外有 `stacked`。不經 ViewModel（純視覺），拖曳視窗時不重建對話列表。
- 各元件在自己的 `Styles` 裡用根節點 class 寫選擇器（例如 `Window.compact TextBlock.collapsible-label`），**RWD 樣式要放在該區的最後**才蓋得過預設值。**只用根節點 Classes**，不用 Container Query、`OnFormFactor` 或在各控制項寫 Converter，避免兩套機制並存。

### 9.3 視窗尺寸

- 工作台預設 1040×760（Wide），`MinWidth` 500、`MinHeight` 420。設定視窗預設 1040×760，最小 720×480。
- 從 1200 縮到 500 不出現水平捲動；測試矩陣至少含 1200×800、900×700、700×650、620×650、520×650、800×560。

### 9.4 各區塊在三段的行為

| 區塊 | Wide（≥ 1000） | Compact（620–999） | Narrow（< 620） |
|---|---|---|---|
| 標題列小精靈按鈕 | 圖示＋「小精靈模式」 | 圖示＋「小精靈」 | 只剩圖示（寬 36） |
| 工具列新對話、歷史對話 | 圖示＋文字 | 32×32 純圖示＋Tooltip | 同 Compact |
| 模型膠囊 | 狀態點＋「供應商 · model ID」＋chevron | 同 Wide | 狀態點＋供應商字首方塊＋model ID |
| 歷史抽屜 | 內嵌 | 內嵌 | Overlay |
| 對話區左右 Padding | 64 | 24 | 16 |
| 助理訊息寬度 | ≤ 820 且 ≤ 內容區 | 92% | 92% |
| 使用者訊息寬度 | 72% | 80% | 80% |
| 時間、「你」、頭像 | 顯示、32 | 顯示、32 | 隱藏時間與「你」、頭像 24 |
| 歡迎區副標 | 顯示 | 顯示 | 隱藏 |
| 訊息動作列 | 圖示＋文字 | 只剩圖示 | 只剩圖示 |
| Composer 外框左右 Margin | 64 | 24 | 16 |
| Composer 下層按鈕 | 圖示＋文字 | 純圖示＋Tooltip | 同 Compact |
| 操作提示 | 顯示 | 隱藏 | 隱藏 |

高度規則：

| 條件 | 行為 |
|---|---|
| Short（< 700） | 輸入框 `MinHeight` 64 → 48（兩行）；訊息間距 24 → 16；歡迎區上 Margin 32 → 8 |
| VeryShort（< 600） | 同 Short，並隱藏歡迎區；工具列、對話區、輸入區仍完整 |

設定視窗 `stacked`（寬 < 900）：AI 連線的清單＋詳細改上下排（清單在上、詳細在下），整頁捲動；小精靈頁的預覽移到上方。小精靈頁不論並排或上下排，頁首與預覽區都固定不捲，只有設定內容捲動（M22）。

## 10. 共用元件與互動狀態

樣式在 `Themes/Controls.axaml`（共用）與 `Themes/ChatStyles.axaml`（對話視窗共用，各 UserControl 以 `StyleInclude` 載入）。元件只引用 token。

### 10.1 按鈕

每個**動作區最多一個 primary**；「測試連線」與「儲存」不能同時是 primary。所有按鈕都必須屬於下列已 token 化的層級（`ButtonCoverageTests` 走訪畫面檢查），新增按鈕時先選層級。

| 層級 | 用途 | 平常 | Hover | Pressed | Disabled |
|---|---|---|---|---|---|
| `primary` | 完成主要任務（儲存、允許、重試） | `PrimaryButton` 底、`PrimaryButtonText` 字（深色模式淺底深字） | `PrimaryButtonHover` 底 | `PrimaryButtonPressed` 底 | `SurfaceAlt` 底、Muted 字 |
| `secondary` | 可逆的輔助操作（測試連線、新對話） | Surface 底、`BorderStrong` 框、Text 字 | `SurfaceAlt` 底 | Soft 底 | 透明底、Border 框、Muted 字 |
| `tertiary` | 低優先動作、圖示按鈕（複製、檔案、「…」） | 無框、Muted 字 | `SurfaceAlt` 底 | Soft 底 | Muted 字、透明度 0.6 |
| `danger` | 只用在破壞性動作（刪除、允許執行） | Surface 底、`DangerBorder` 框、Danger 字 | `DangerBackground` 底 | 同 Hover，框換 Danger | 透明底、Border 框、Muted 字 |

- `PrimaryButtonHover`／`PrimaryButtonPressed` 是 `PrimaryButton` 往 `Background` 混合 12%／24%（primary 淺色底已近黑，無法「再深」）；五套 × 淺深各有一組並有對比測試。
- 其他經過 token 化的專用樣式：送出圓鈕 `round send`（Accent 底、Hover／Pressed `AccentHover`、Disabled Soft 底）、停止圓鈕 `round stop`（同 primary 狀態）、標題列「小精靈模式」`spriteMode`（Soft 底）、虛線「新增」入口 `dashed`、`chrome`、`link`（小精靈氣泡）、`cardheader`／`groupheader`（整列標題，Hover 不換底）、`md-copy`、`ToggleButton.secondary`、分段切換。
- 尺寸用的輔助 class（`toolbar`、`small`、`iconOnly`、`collapsible`、`composer-tool`、`capsule`、`confirm`、`message-action`、`chip-remove`、`round`）只管尺寸，必須和層級 class 並用。
- **純圖示按鈕必須有 `ToolTip.Tip` 與 `AutomationProperties.Name`**。停用的按鈕要用 `ToolTip.ShowOnDisabled="True"` 並在旁邊或 Tooltip 寫出原因；錯誤一定有文字，不能只改顏色。

### 10.2 焦點框

鍵盤（Tab、方向鍵）才出現，滑鼠點擊不出現：**Accent 2px 圓角**，畫在按鈕自己的外緣內側（圓角同按鈕：一般 10、圓鈕 18、膠囊 16），取代 Fluent 預設的黑白雙框。自己畫焦點外觀的元件（`dashed` 的虛線框、分段切換、進階區段標題、卡片清單項目）把 `FocusAdorner` 設為 null，只有一個 Accent 框。

### 10.3 輸入框與下拉選單

- **TextBox／ComboBox**：高 40（多行輸入框的高度由使用處設定）、圓角 10、邊框 1 `BorderStrong`、Surface 底、Padding 12,8（深色模式是主題的深灰 Surface，不是純黑）。
- Hover：邊框換 `AccentBorder`。**Focus**：Accent 邊框加外圈 3px 的 Soft 光暈（TextBox／ComboBox 沒有 `BoxShadow`，模板內多一層透明外框 `PART_FocusGlow`，Margin -3，Focus 時顯示）。錯誤：加 `error` class，Danger 邊框，**一定要同時顯示錯誤文字**。停用：`SurfaceAlt` 底、Muted 文字，並另外寫出停用原因。
- 欄位用 `FormField`：標籤（14／700）永遠在輸入框上方，右側「必填／選填」，說明 Caption 在下方，錯誤文字（Danger）在說明下方；Placeholder 不取代標籤。
- `embedded` 樣式（沒有框與光暈）用在小精靈輸入列與 Composer 的輸入框，外框由外層元件負責。NumericUpDown 的外框同一套 token，但高度仍是 Fluent 的 32，與 40 高的 TextBox 不一致（已知）。

### 10.4 卡片、分隔線、徽章、清單項目

- **卡片**（`card`）：Surface 底、1px Border、圓角 14、Padding 16。只用來代表**一個物件**（連線、模型設定、角色、工具卡片、色票、資訊卡）；巢狀最多一層；只有可點擊的卡片才有 Hover（陰影 `LumiCardHoverShadow`）；選取＝Soft 底加 `AccentBorder` 邊框，並保留文字狀態（「使用中」）。**不要把整份表單或每個欄位包成卡片。**
- **分隔線**（`divider`）：1px Border 色，上下間距 16；用來區分群組，不是每個欄位下面都畫一條。
- **狀態徽章**（`badge`）：Soft 底、圓角 12、Caption 的 `TextOnSoft` 文字（例如「連線正常」「使用中」）；不能只用顏色或圓點表達狀態。
- **清單項目**（`ListBoxItem`、`ComboBoxItem`）：Hover＝`SurfaceAlt` 底；選取＝Soft 底加 `TextOnSoft` 文字（圓角 10）；停用＝Muted。`ListBox` 本身不畫底色。
- 其他：`MenuFlyout`／`Flyout` 外框 Surface 底、Border 框、圓角 12，MenuItem 的 Hover／Pressed／停用同上；CheckBox／RadioButton 用 Accent；ScrollBar thumb `BorderStrong`（Hover 變 Muted）；ProgressBar 進度 Accent、軌道 Border；進階區段（`Expander.advanced`）無框、Muted 標題加 chevron。ToolTip 目前仍是 Fluent 預設樣式。

### 10.5 Avalonia 陷阱（寫樣式前必讀）

1. **Fluent 把 Hover／Pressed／Disabled 的底色與字色設在模板內的 `ContentPresenter#PART_ContentPresenter`**，優先於直接設在 Button 上的 Background／Foreground／BorderBrush（那只是 TemplateBinding）。所以只在 Button 上寫 Background，平常看起來對，一 Hover 就變成 Fluent 的半透明黑底加黑字（深色模式尤其明顯）。**每個狀態都必須用 `/template/ ContentPresenter#PART_ContentPresenter` 選擇器覆寫**；前景色設在 ContentPresenter 上，內容裡的 TextBlock 與 `LumiIcon` 會繼承。Pressed 時 `:pointerover` 也成立，所以 Pressed 要寫在 Hover 後面，Disabled 放最後。`ListBoxItem:selected` 的底色同理（畫在模板的 ContentPresenter，不是 ListBoxItem）。
2. **帶偽類別條件（`:unchecked`、`:pointerover`、`:disabled`…）的 setter，優先權高於不帶條件的 setter，也高於模板內的 TemplateBinding。** 所以在模板零件上寫「正常」狀態時要小心：CheckBox／RadioButton 每個狀態都寫成「選取狀態＋互動狀態」的完整組合；NumericUpDown 箭頭的正常狀態用 `RepeatButton:not(:disabled)`；ScrollBar 要分 `:vertical`／`:horizontal`。

新增或調整樣式後，跑 `ButtonStateStyleTests`、`InteractiveStateStyleTests`、`FluentColorResidueTests`（掃描五套主題 × 淺深所有元素，不能殘留 Fluent 預設色）確認沒有被蓋掉。

## 11. 啟動失敗視窗（M9 9C）

啟動流程的任何階段失敗（DI 組裝、主機啟動、設定檔讀取、資料庫開啟、啟動時載入對話）都顯示這個說明視窗，不讓程式無聲消失。

- **不依賴 DI**：DI 組裝失敗時也能顯示。只用資源的 token（預設色票由 `ThemeService.ApplyPalette` 的靜態方法套用），文字來自 `Strings`，報告在建構前就組好。
- **版面**：視窗寬 480、高度自動、不可縮放、螢幕中央。標題「Lumi 無法啟動」（`LumiFontSizeTitle`），一句原因，「記錄檔資料夾」（Caption 標籤）加路徑（可選取複製）。
- **原因分類**（`StartupFailureClassifier`，依型別與錯誤碼，不看訊息文字）：
  - 資料庫被其他程序鎖住（SQLITE_BUSY／LOCKED）：「資料庫正被其他程序使用中，Lumi 可能已經在執行。……」。只做說明，不做單一實例鎖。
  - 權限不足（UnauthorizedAccessException、SQLITE_READONLY／PERM）。
  - 磁碟空間不足（磁碟已滿的 IOException 錯誤碼、SQLITE_FULL）。
  - 資料庫由較新版本的 Lumi 建立（`DatabaseTooNewException`）。
  - 設定檔無法讀取（`SettingsFileUnreadableException`；損毀的 JSON 不在此列，仍是改名保留並用預設值）。
  - 其他。
- **按鈕**：「結束」是 `primary`（預設按鈕，視窗唯一的 primary）；「複製詳細資訊」是 `secondary`，複製後在按鈕上方顯示 Caption「已複製到剪貼簿。」。「結束」與視窗的關閉鈕都結束程序，結束碼非 0。
- **詳細資訊**（複製的純文字）：時間、Lumi 版本、作業系統、執行環境、分類、資料夾位置、例外型別（含內層，最多 5 層）與訊息。訊息經過遮蔽：使用者資料夾換成 `~`，`sk-…` 之類的金鑰、`Bearer …`、`api_key=…`、32 字元以上的英數字串換成 `[遮蔽]`。不含聊天內容與設定檔內文。
- **記錄**：寫進使用者資料夾的 `logs/lumi-yyyy-MM-dd.log`（Information 以上，`Microsoft.*` 只記 Warning 以上）。說明視窗顯示的是這個資料夾。
- **其他未處理例外**（M9 9C）：寫進 log、不彈窗（啟動階段由本視窗處理）。背景工作的未觀察例外標記為已觀察；UI 執行緒的例外記錄後不標記為 Handled，照舊由 Avalonia 處理。

## 12. 工作台視窗記憶（M9 9D）

工作台主視窗關掉再開，回到上次的位置與大小；最大化狀態也會保留。小精靈的位置另外記（`SpriteSettings.Placement`），設定視窗每次都置中，兩者不在這裡。

- **記什麼**：視窗左上角（螢幕像素）、用戶端寬高（DIP）、是否最大化、存檔當下所在螢幕的縮放比例。存在使用者資料夾的 `settings.json`（欄位 `workbenchWindow`，和其他設定同一個檔案）。
- **不記什麼**：最小化狀態；隱藏中（切到小精靈模式）的位置與大小；最大化時的尺寸（最大化時只把旗標設為 true，位置與大小沿用最後一次正常狀態的值）。
- **何時寫入**：移動或縮放時節流 500 ms 才寫一次，寫的是那段時間內最後的值；關閉視窗時再寫一次（等待上限 500 ms，寫入失敗只記 log）。設定檔寫入不通知其他設定頁重載。
- **還原**：開啟時套用。寬高小於視窗最小尺寸（500×420）、大於所有螢幕工作區的聯集、縮放比例不合法，或標題列區域（左上角 100×40 DIP）沒有完整落在某一個螢幕的工作區內，都退回**置中的預設大小**（1040×760）。拔掉外接螢幕後，記住的位置在螢幕外，就會退回預設，不會開在看不見的地方。
- **縮放**：寬高以 DIP 還原（邏輯大小不因螢幕縮放改變）；範圍檢查以目標螢幕目前的縮放把 DIP 換算成螢幕像素。位置一律是螢幕像素。
- **讀不進來**：`workbenchWindow` 格式錯誤只忽略這一欄（視窗置中），不會把整個設定檔當成損毀，也不跳出「設定檔損毀」提示。
- 實作：`WindowPlacementRules`（純函式）、`WindowMemoryRecorder`（節流）、`WorkbenchWindowMemory`（接線），`WindowSettings.Normalize` 處理不可信的值。

## 13. 提醒通知（M10 10E）

提醒到點（或錯過的彙總）時，只在 Lumi 自己的畫面顯示；系統通知留給 M11（需要打包後的應用程式識別）。Lumi 沒有在執行時不會觸發，這點寫在提醒工具的說明裡，模型不應承諾「一定會準時叫你」。

- **送達**：`INotificationSink` 的 App 實作 `NotificationCenter`（單例）。通知只存在記憶體，最多保留 20 則，超過丟掉最舊的；同一個 Id 不重複加入。
- **不自動消失**：不論小精靈或工作台，提醒都留到使用者按關閉才收起。
- **兩個視窗各自顯示**（兩者不同時存在，但各自有自己的呈現），同一則通知不會在同一個視窗重複出現：
  - **工作台**：內容區頂端（標題列與工具列之下、對話之上）的通知列。每則一張橫條卡片：鈴鐺圖示、標題（粗）、內容（最多 3 行，超過截斷）、關閉鈕。最多顯示最新 3 則；超過時尾端顯示「還有 N 則」與「全部關閉」。錯過彙總用較中性的底色與灰色圖示。Wide、Compact、Narrow 的左右邊界同輸入區（64／24／16），Narrow 時關閉鈕不會擠壓內容。沒有通知時整列不佔空間。
  - **小精靈**：氣泡區最上方的提醒卡片，位於回應氣泡之上（兩者可同時存在，互不覆蓋）。只顯示最新一則，超過時標示「還有 N 則」；關掉一則後顯示下一則。內容沿用氣泡的字數上限截斷（完整內容在工作台的通知列）。卡片只有關閉鈕會攔截滑鼠，其餘部分點擊穿透。
- **都沒有顯示時自動顯示小精靈**：新提醒加入時，若工作台與小精靈都不可見（小精靈暫時隱藏且工作台已關閉），要求顯示小精靈，並提前結束「暫時隱藏」。**只在作用中模式是小精靈時才這麼做**：工作台模式下關掉工作台就是結束程式，不存在「工作台模式但沒有視窗」的正常狀態；啟動時（模式協調者的 `Start()` 之前）視窗還沒顯示，這時不能呼叫 `ShowSprite()`，否則會把模式切成小精靈、之後 `Start()` 又開工作台，變成兩個視窗同時開（通知仍留在清單，視窗出現後就看得到）。已經有可見視窗時不會主動切換模式，也不會打斷回應中的對話。
- **錯過的提醒**：程式啟動或睡眠喚醒後，錯過的一次性提醒彙總成一則「錯過的提醒」通知（`MissedSummary`）；週期提醒補一次。
- **系統通知**（Windows toast、macOS 通知中心）不在這一版範圍，留給 M11；屆時只需新增一個 `INotificationSink` 實作。
- 實作：`NotificationCenter`、`NotificationItemViewModel`、`NotificationStripViewModel`（工作台列的「最新 3 則」邏輯）、`NotificationStrip`（工作台列的畫面）、`SpriteBubbleViewModel` 的提醒屬性（`BindReminders`）、`SpriteBubbleView` 的提醒卡片。
