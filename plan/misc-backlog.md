## #8 空回應：調查方向

現象：送出後模型跑了很久，結束時回應是空的，畫面沒有錯誤。發生時的模型、連線、模式（工作台／小精靈）、是否開思考、是否有工具呼叫：**尚未記錄**，查之前先回想或從 log 找。

可疑方向（撰寫時未驗證）：

- **思考用完了輸出額度**：開了思考，思考就把 `max_tokens` 用完，`stop_reason` 是 `max_tokens`，沒有任何文字區塊；思考收合或不顯示時，看起來就是空的。
- **只有思考、沒有文字**：回應只有 thinking 區塊，畫面沒把它當成「有內容」。
- **OpenAI 相容的 `finish_reason`**：`length`、`content_filter` 沒被當成錯誤處理（例如 Azure 內容篩選擋下時回傳空內容）。
- **串流中途斷線但沒有拋錯**：Gateway 或 Proxy 逾時後正常關閉連線，`Completed` 照常發出。
- **工具迴圈的最後一輪沒有文字**：最後一次回應只有 tool_use，或撞到 `MaxIterations` 後沒有顯示原因。
- **小精靈的回答被截斷規則清空**：兩句、約 60 字的限制處理到變成空字串。

查的時候順便確認：

- 空回應（沒有文字區塊）時，畫面要顯示原因與「重試」，不要靜默結束。可以照 `stop_reason`／`finish_reason` 分別寫出說明。
- log 要記下 `stop_reason`／`finish_reason`、輸出 tokens、是否有思考區塊。
- 這類請求的 token 照樣計費，`plan/23-usage-cost.md` 的 `request_usage` 要照常記錄，可以加一個欄位標記「沒有產出文字」，方便之後統計發生頻率。

## #9 MCP 快速接入

2026-10-31 記錄。目標：使用者不需要懂 JSON、不需要自己裝 Node／Python、不需要手動管理金鑰，就能把現成的 MCP 接進 Lumi。

**M16 已經做到的**（見 [16-mcp.md](16-mcp.md)，程式完成、待人工驗收）：stdio 與 Streamable HTTP、貼上 `mcpServers` JSON 匯入（先預覽再寫入）、祕密存進 `ISecretStore`、測試連線與易懂的錯誤文字、MCP 工具逐一設定權限等級、預設只在工作台、macOS 用登入 shell 的 PATH、Windows 解析 `npx.cmd`。

**M16 明確不做、這個項目要補的**（對照 16-mcp.md「不做」清單）：

| 缺口 | 想法 | 備註 |
|---|---|---|
| 執行環境 | 偵測 Node（`npx`）、Python（`uvx`）、Docker、.NET 是否存在；缺少時提示並提供一鍵安裝，或內建可攜版 | 目前找不到指令只會顯示「找不到指令」。可攜版的授權與體積待評估 |
| OAuth | 遠端 MCP 需要 OAuth 時，由 Lumi 開瀏覽器並接回授權結果 | M16 只做自訂標頭 |
| 目錄與一鍵啟用 | 先放少量驗證過的常用 MCP；之後再考慮接官方註冊表搜尋 | 註冊表與 `.mcpb` 的現況沒有查證，實作前先查官方文件 |
| 其他入口 | 貼上遠端網址、套件名稱或 GitHub 連結；拖入 `.mcpb` | 都轉成 M16 既有的 `McpServerSettings` |
| 環境變數表單 | 匯入時把環境變數轉成有說明的欄位，不要只貼 JSON | M16 已有名稱＋值的列，缺的是說明文字 |
| 安全提示 | 首次啟用第三方套件前顯示來源、固定版本並確認 | 執行第三方套件等於執行任意程式碼；D15 目前只有文字警告 |
| 工具數量 | 接很多 MCP 時，工具描述會吃掉上下文；考慮依情境啟用或延遲載入 | 小精靈模式特別需要 |

**建議順序**：先做執行環境偵測與提示（成本最低、最常卡住），再做環境變數說明與安全提示，OAuth 與目錄放最後。

**待釐清**：各家 MCP 實際的設定樣本要先蒐集；內建可攜執行環境的授權與體積；`.mcpb` 與官方註冊表的目前規格。
