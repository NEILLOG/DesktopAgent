# Lumi 光球 POC

只驗證「小精靈視窗」最沒把握的五件事。沒有 API、沒有錄音、沒有工作台。
光球全部用程式繪製（漸層橢圓 + 變形矩陣），不使用圖片、也不使用 BlurEffect。

## 執行

需要 .NET 10 SDK。

```bash
cd poc/Lumi.OrbPoc
dotnet run -c Release
```

- 量測耗能一定要用 `-c Release`；Debug 的數字會偏高。
- 啟動參數：
  - `--no-clickthrough`：關閉點擊穿透
  - `--no-layered`：僅 Windows，不加 `WS_EX_LAYERED`，詳見下方「已知風險」

## 操作

| 動作 | 結果 |
|---|---|
| 游標靠近光球（150 DIP 內） | 睜眼、看向游標、浮出輸入列與招呼氣泡 |
| 點一下光球 | 依序切換 10 種示範狀態 |
| 按住光球 0.45 秒不動 | 被戳：凹陷、>_<、腮紅；放開後 QQ 回彈 |
| 按住後移動超過 4 DIP | 拖曳（光球果凍晃動、眼睛轉圈）；放開後自動夾回螢幕內 |
| 輸入文字後按 Enter | 跑一次假對話：思考 → 呼叫工具 → 逐字回覆 → 完成 → 待機 |
| 麥克風按鈕 | 跑一次假語音流程：聆聽 → 轉寫 → 假對話（不會錄音） |
| 右鍵光球 | 選單：示範狀態、眼睛模式、大小（64／80／104，預設 80）、HUD、點擊穿透、自適應幀率、拖曳方式、結束 |
| F1（視窗有焦點時） | 開關診斷 HUD |
| 待機且沒人靠近 60 秒 | 自動休眠；游標靠近時喚醒 |

## 已知風險（就是這次要確認的）

- **Windows 點擊穿透**
  - 頂層視窗一般需要 `WS_EX_LAYERED` 加上 `WS_EX_TRANSPARENT` 才能讓滑鼠穿過。
  - 加上 LAYERED 之後，Avalonia 的透明渲染可能出問題，例如畫面消失或變黑。
  - 如果發生，改用 `--no-layered` 再測一次，看只切換 `WS_EX_TRANSPARENT` 夠不夠。
  - 兩種都不行的話，備案是把視窗縮到只包住光球，輸入列另開一個小視窗。
- **macOS 全螢幕 App**
  - 已經設定 `CanJoinAllSpaces` 與 `FullScreenAuxiliary`。
  - 如果還是看不到，可能要把 App 改成 accessory 模式（不顯示 Dock 圖示）。這部分正式版再處理。
- **拖曳抖動**
  - 手動設定 Position 在某些平台可能有一幀延遲，所以留了系統拖曳模式可以比較。

## 程式結構

```
OrbControl.cs              光球繪製與動畫（配色、呼吸、眼睛、戳、拖曳形變、漣漪、弧線、粒子）
MainWindow.axaml(.cs)      透明視窗、輸入列、氣泡、靠近偵測、戳/拖判定、假對話、右鍵選單、HUD
Platform/                  原生部分：游標輪詢、點擊穿透（Windows: Win32，macOS: objc_msgSend）
Diagnostics/FrameDriver    動畫時鐘：60fps 跟螢幕刷新，30/12fps 用計時器讓程式真正休息
Diagnostics/PerfMonitor    FPS、CPU、記憶體取樣
```

正式開發時，`OrbControl`、`Platform/`、`FrameDriver` 可以直接沿用。
